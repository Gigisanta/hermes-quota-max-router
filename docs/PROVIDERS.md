# LLM Providers — June 2026 Snapshot

The router speaks to providers through two layers that merge at runtime:

- **Curated tier** (`registry/models.json`) — 4 hand-picked, manually-verified
  models. Stable IDs, tier 1–4, source of truth for ranking.
- **Discovered tier** (`registry/discovered.json`) — auto-pulled from
  OpenRouter and HuggingFace; tier 10+; refreshed on demand by
  `python -m scripts.operations auto-update live`.

The merged registry is what `/v1/models` returns, what
`/v1/router/health` reports in `models_count`, and what the orchestrator
scores against.

## Discovered tier

`registry/discovered.json` is regenerated by the Auto-Updater from three catalogs in `core/catalogs.CATALOGS`:

- **OpenRouter public** (`https://openrouter.ai/api/v1/models`) — pulls every model OpenRouter lists with real USD pricing. `_parse_openrouter` flags `is_free = (prompt == 0 and completion == 0)`, infers `context_length`, and attaches `vision_master` / `multimodal` when `input_modalities` contains `image` or `file`. All OpenRouter entries start at `tier_rank: 10` and `daily_quota_tokens: 10_000_000` (best-effort estimate).
- **HuggingFace warm-inference** (`https://huggingface.co/api/models?inference=warm&filter=text-generation&limit=200`) — caps at 200 entries; `is_free` is True only when the model is not private, not gated, and has an `inference_provider` field. HF tags are mapped to our schema (`coding_sota` / `vision_master` / `long_context_king` / `instruction_following_god`). All HF entries start at `tier_rank: 20` and `daily_quota_tokens: 1_000_000`.
- **Curated static fallback** — re-reads `registry/models.json` so the auto-updater always has the 4 hand-picked entries even with zero network.

Network failures degrade gracefully: if OpenRouter is unreachable, you still get HF + curated; if both network sources fail, you still get curated. Each catalog is fetched independently with a 15s timeout.

## Adding a new free model

Three ways, in order of how often you want to use them:

### 1. Auto-discovery (the default path)

Run the auto-updater against the live remote feeds; any model that's
currently listed on OpenRouter with `pricing.prompt == 0 and pricing.completion == 0`,
or any HuggingFace warm-inference model that's public, will be picked up
automatically:

```bash
python -m scripts.operations auto-update live
```

The next `GET /v1/models` returns the new entries. `registry/discovered.json`
and `registry/data/registry_discovered.sqlite` are rewritten. **Use this
99% of the time.**

### 2. Local feed file (offline / staging)

Drop a JSON file in the same schema as `registry/models.json` and apply it
via the dashboard's **Updater** tab or via CLI:

```bash
python -m scripts.operations auto-update path/to/feed.json
python -m scripts.auto_updater path/to/feed.json      # alias
```

The schema is the same as a single entry in `registry/models.json`:

```json
{
  "model_id": "provider/model-name",
  "provider": "provider",
  "display_name": "Display name",
  "context_window": 131072,
  "input_price": 0.0,
  "output_price": 0.0,
  "is_free": true,
  "tier_rank": 5,
  "daily_quota_tokens": 5000000,
  "strength_tags": ["deep_reasoning", "tool_master"],
  "weakness_tags": [],
  "best_for": ["planning", "multi_step_agents"],
  "performance_score": 88.0
}
```

`RegistryUpdater.apply_feed()` will ADD new IDs, UPDATE changed fields, and
skip entries that already match. Errors are collected in `UpdateResult.errors`
and returned in the response — they don't abort the rest of the merge.

### 3. Curated entry (promotion to tier 1–9)

Edit `registry/models.json` directly, add a model with `tier_rank <= 9`, and
restart the router. Use this only for models you want the orchestrator to
**prefer** over the auto-discovered pool. The curated layer always wins on
conflict with the discovered layer (`LayeredRegistry` semantics), so a curated
entry will shadow the same `model_id` from the discovered feed. This is the
right tool for promoting a model after a benchmark pass.

## Removing a model

Two ways:

### 1. Curated remove

Delete the model entry from `registry/models.json` and restart the router.
The next `auto-update live` will not re-add it because the curated layer
takes priority on conflict — but if the same `model_id` exists in the
discovered feed it will reappear there. For a hard curated remove, also
delete from `registry/data/registry_curated.sqlite` (or run
`python -m scripts.operations auto-update live` with a feed that omits the
entry and a `RegistryUpdater(remove_missing=True)` — but that's the nuclear
option, default is `remove_missing=False` to avoid wiping models on a
temporary feed gap).

### 2. Discovered prune

`registry/discovered.json` is generated; editing it manually is overwritten
on the next `auto-update`. To suppress a model from the discovered layer
permanently, either:

- Wait for the upstream catalog to drop it (most `:free` models come and go).
- Pin it as `is_free: false` in a curated override — the curated layer wins,
  the discovered entry is shadowed, and the orchestrator skips it.
- Filter at the `Catalogs` level by editing `core/catalogs.py` (e.g. add
  a `free_filter` that drops the vendor) and re-run auto-update.

In practice, free models are removed automatically: when an upstream flips
`is_free` to False, the next auto-update marks the entry paid, and the
orchestrator's `is_free` filter skips it for `preserve_paid_quota=True`
decisions. The model stays in the registry as a paid fallback for when free
quality is insufficient.
